# Feature reference

> **Tested only on firmware 12.40 with a PS5 Pro.** Performance on a base PS5 is unknown - see [compatibility.md](compatibility.md).

All mods are entries in `cheats/CUSA03173_01.09.json`, generated by the scripts in [`tools/mods/`](../tools/mods/). "On" bytes patch the running game at launch; "off" bytes restore the original instructions, so every mod can be toggled in the onionHEN cheat menu. For the technical background of each one see [research/](research/README.md).

## Stable mods

### 60 FPS (Lance McDonald) - default on
Unlocks 60 FPS by patching the frame-rate cap, the simulation time step and related constants. The patch list is derived from **Lance McDonald's Bloodborne 1.09 60 FPS patch** (see [CREDITS.md](../CREDITS.md)); here it is applied to the running game instead of rewriting `eboot.bin`. This repository does not contain his executables. If you like the result, please support the original author.

### No Motion Blur / No Chromatic Aberration / Skip Intro Logos - default on
Small byte patches that disable the motion-blur pass and the chromatic-aberration effect, and blank the start-up logo videos.

### Wide FOV (x1.3 by default) - opt-in
The follow camera converts the camera parameter's field of view (base 43 degrees vertical, clamped by the game to 38..48) to radians with one multiply. The mod redirects that multiply to a constant in a code cave (`pi/180 * scale`), so every camera row gets the same multiplier and the game's cap no longer applies. x1.3 is about 56 degrees vertical / 87 horizontal at 16:9; x1.5 is about 64 / 97; x1.8 is about 77 / 110. The first-person camera was tuned at x1.8: while the head camera is on, the head-camera cave switches the constant to the first-person multiplier (default x1.8, `--fps-fov`; x1.5 up to v1.1.0) and back to the Wide-FOV value in third person, so each view keeps its own field of view. Change the values with `tools/mods/build_cheats.py --fov-scale X --fps-fov Y`, or live by writing the float at `0x54A0500` (`tools/dev/mods-live/fov_live.py`).

### DLAA threshold 0.3 - opt-in
The game already runs its own **DLAA** anti-aliasing pass (this was found during the research: the "AA" in the game is not the FXAA that the YEBIS library offers). The pass reads its edge-detection threshold (default 0.1) from a parameter block; the mod loads 0.3 instead through a small cave. Measured on pose-locked scenes it is sharper than the default (+3.2 % / +1.7 % normalised Laplacian sharpness in the two valid scenes; 0.45 would give +5.6 % / +3.2 % at the cost of more visible aliasing) and was the clear favourite in side-by-side blink tests, while plain FXAA2/FXAA3 were the worst. The comparison tool on the site shows the difference. Other values can be built with `tools/mods/make_dlaa_mod.py`.

### Anisotropic filtering 16x - opt-in (little or no visible effect)
Redirects the game's sampler set-up so that the anisotropic samplers get `MaxAnisotropy = 16` (the game ships with 4). In the controlled pose-locked scenes **no measurable change appeared** - even switching anisotropy off entirely changed nothing there (an early +9 % reading turned out to be fog drift). The mod works mechanically and is included for completeness and for anyone who wants to investigate; do not expect a visible improvement. Details: [research/03](research/03-anti-aliasing-and-image-quality.md).

### No depth of field - opt-in (scene-specific, mild)
Passes "false" to the depth-of-field enable call every frame. The effect depends on the scene: a far-distance Hunter's Dream test scene showed a measurable change in its farthest regions; two Yharnam scenes showed none. Treat it as a taste option.

### DLC Save Requirement Unlock - opt-in
Sets the DLC-ownership flags so that saves which require the DLC can be loaded.

## Experimental: the FPS head camera

A first-person camera attached to the character's head. It replaces only the **position** of the camera that the camera manager hands to the renderer; the game's own camera logic (right stick, collision logic, look-at) keeps running, so the view direction is still the game's. Details:

- **Head source:** world-space bone matrices of the player's skeleton (bone 68 is the head). The location of these arrays inside the game's objects changes between sessions and after a respawn, so the cave validates and re-discovers them itself; if it cannot find them it falls back to a fixed standing head height instead of leaving first person.
- **Smoothness:** in some maps the animation pose updates at 30 Hz while the game runs at 60. The cave takes the character's 60 Hz position and adds the animated head offset, smoothed over a few frames, so movement stays at 60 Hz and head bobbing stays soft.
- **Height floor:** the camera never goes lower than 1.25 m above the character's feet, so rolls and stumbles do not drop the view into the body (walking bob is not cut).
- **Death camera:** when the player's HP reaches 0 the camera keeps following the head as the body falls: the height floor is lifted and the view direction follows the head bone (forward = the bone matrix's third column, up = the first; eased from the game's last view and re-orthonormalised) instead of staying fixed. The camera never sinks below the feet + 0.30 m (`DFLOOR`), so it does not clip into the ground. The body-facing option is suspended while dead. After the respawn everything returns to normal by itself. Death is read from the HP field `[[pl+0x3b0]+0x20]+0xf8`.
- **Death slow motion** (own option, needs the head camera): the death plays at normal speed for the first 5 s (300 frames), so the death animation and the "YOU DIED" screen arrive just as in the plain game; at that moment every character drops to 5 % speed until 12 s after the death (about 6.5 s of slow motion: the enemies that killed you move around your body in slow motion while the text fades in), then time returns to normal and the game goes on to the respawn. It scales the speed factor every character multiplies its time step with (`[[chr+0x3b0]+0x30]+0x374`, read at `0x1E196BB`), so the player and all enemies slow down together; effects, cloth and the camera smoothing keep running in real time. It is reset to normal time whenever the head camera is off or the player object disappears (loading). Two phases are configurable and live-tunable: phase 1 (`PH1SCALE` 1.0 for `PH1END` 300 frames), phase 2 (`PH2SCALE` 0.05 until frame `PH2END` 720), easing `SLOWG` 0.25 per frame. Other profiles are possible, for example 10x speed for the first 20 frames makes "YOU DIED" appear within a second (the game's death timeline runs on game time), at the cost that the later parts of the sequence also arrive early.
- **Killer camera** (own option, needs the head camera): from the first frame of the death the view looks at the character that killed the player instead of tumbling with the head. The target is chosen once per death: the locked-on enemy if there was one, otherwise the nearest living character within 20 m (characters are read from `[WorldChrMan+0x1490]`, 0x38-byte records, count at `+0x1488`; HP `[[chr+0x3b0]+0x20]+0xf8`). The view is eased towards the target's chest (+1.3 m, `KHEIGHT`) with the world up vector (no roll) from the camera at the head's position on the ground; `LOCKAT` (default 0) delays the turn by that many frames. If the target disappears the head-following death camera continues.
- **Close-character guard:** a visceral attack (after a parry) puts the player's body inside the enemy; a head-mounted camera would then be inside the enemy's coat. While the camera is closer than 0.5 m to the torso point (feet + 1.0 m) of a living character, and for 1.5 s after that, the game's own camera is left alone (a cut to the normal view for the riposte). It is off while dead. Live-tunable: `NEARR2` (squared distance, 0 disables), `NEARHOLD`, `NEARTORSO`. A first version compared feet positions horizontally and fired for invulnerable map objects (HP 999/9999) that stand next to the player.
- **Camera collision off:** the six wall-collision casts of the follow camera return "no hit"; otherwise the camera is pulled in against walls and the orientation spins.
- **Offsets:** right/up/forward from the head bone = 0 / 0.30 / 0.32 m (eye position, 0.17 up to v1.1.0; the forward value 0.32 keeps a worn hood out of the picture - with the head slot empty `OFF_F` can be lowered to about 0.05, see the research notes; the face of the model stays behind the camera while walking and backpedalling, and the weapons are well visible in the hands).
- **Switching it in game:** double-click the touchpad (two clicks within about half a second) to switch between the first-person and the normal camera, for example to reset it if something looks wrong. The game opens and closes its personal-effects menu with those clicks, which is harmless. The check runs even while the head camera is off. It reads the controller's report buffer from the pad library's data segment (the library's code is execute-only and is never read).
- **Safety:** every pointer is range-checked and every object identified by its vtable before it is touched. If a check fails the cave does nothing and the game's normal camera is used.

Companion options (both need the head camera):

- **Body faces the view** - rotates the displayed model so the body follows the camera direction instead of the movement direction (strafing and backpedalling still work because only the display changes). It acts **only while the head camera is on**: switching to third person (touchpad double-click) restores the normal body. **Side effect: the coat/hood cloth disappears while it is on** (it returns when the camera is off or the option is switched off). Tested from a cold start on a PS5 Pro; it is enabled in the `_fps` profile.
- **Aim at the lock-on target** - the game's lock-on camera looks at the player's pivot, not at the enemy; with the camera at the head that puts the target above the centre line. This option reads the locked target from the camera manager and keeps the view pointed at it (the offset is stored in camera space and stays after releasing the lock until you turn the camera). Experimental: close-range strafing can still twitch. Other people are invited to build better profiles on top of it (see [agents/90-open-questions.md](agents/90-open-questions.md)).

## VRR for PS4 games (host tool, not a cheat)

Not part of the cheat file: [`tools/vrr`](../tools/vrr/README.md) enables VRR for the running PS4 game by editing the system video service's capability record (48-60 Hz), optionally switches the link to 1080p 119.88 Hz VRR (48-120 Hz) with a three-part code patch in the same service, and caps Bloodborne's frame rate inside the VRR window (up to 118 FPS on the 120 Hz link). Results, usage, limits and safety: [vrr.md](vrr.md). Tested only on firmware 12.40, a PS5 Pro, Bloodborne and one display.
