# 00 - Orientation: architecture and glossary

> Tested only on **firmware 12.40 with a PS5 Pro**, game **Bloodborne GOTY `CUSA03173` v01.09**. Behaviour and performance on a base PS5 and on other firmware or game versions are **unknown**; never claim otherwise. See [../compatibility.md](../compatibility.md).

Read [../../AGENTS.md](../../AGENTS.md) first (rules, quick starts, checklist). This file explains how the pieces fit together and defines the vocabulary used in every other document.

## 1. What the project is

A set of **image-quality and gameplay mods** for Bloodborne on a jailbroken PS5. Each mod is a list of **memory patches at fixed virtual addresses inside the running `eboot.bin`**, delivered as an **onionHEN cheat file** (JSON). Nothing on disk is modified: onionHEN writes the patches into the game process right after it starts (exec time) and can switch them on and off later.

Mods in the release build (`cheats/CUSA03173_01.09.json`, generated by `tools/mods/build_cheats.py`):

| Mod (menu name) | Kind of patch | Default |
|---|---|---|
| 60 FPS (Lance McDonald) | 128 small byte patches (frame limiter, time step, fix-ups); credit in [../../CREDITS.md](../../CREDITS.md) | on |
| No Motion Blur | 1 byte patch (`je` -> `jmp`) | on |
| No Chromatic Aberration | 12 byte patch | on |
| Skip Intro Logos | 3 string heads zeroed | on |
| Wide FOV xN | 1 constant in a cave + 1 redirected `disp32` | off (profiles enable it) |
| DLAA threshold 0.3 | 5-byte hook + 13-byte cave + 1 float | off |
| Anisotropic filtering 16x | call-site redirect + 134-byte stub | off (known: no measurable effect, see [80](80-experiments-log.md)) |
| No depth of field | 3-byte inline patch | off |
| FPS head camera (+ FACE2, + AIM, + death slow motion, + killer camera) | 4 hooks, 4 caves (486 B / 27 B / 3387 B / 22 B), 0x1D8-byte data block, touchpad double-click toggle | off |
| DLC Save Requirement Unlock | 8-byte patch | off |

          |                                                 +---------------------------------------------+

Ports used by the tooling (all TCP, on the console address `<console-ip>`; scripts read it from the environment variable `PS5_HOST`):

| Port | Service | Used for |
|---|---|---|
| 744 | ps5debug-NG | process list, memory read/write, memory map, debugger attach |
| 755 | on the **bridge host** | the console connects back here after a debugger attach (needs root to bind) |
| 2121 | ftpsrv | upload cheat JSON and ELFs, read screenshots, small control files |
| 3232 | klogsrv | stream the console kernel log (game start, fatal signal, onionHEN log lines) |
| 9021 | elfldr | send a raw ELF to execute (e.g. toast payload, OnionHEN.elf) |
| 9048 | onionHEN stack command | frame `<II` `0x4F4E494F, 1` = shut the onionHEN stack down (restarts ShellUI: black screen about 5 s) |

Setting up the jailbreak chain itself (WebKit autoloader, elfldr, kstuff-lite, ps5debug-NG, onionHEN) is out of scope; see [../../CREDITS.md](../../CREDITS.md) for the projects involved.

### What happens when the game starts (patched onionHEN)

1. The human launches Bloodborne. The kernel log shows `Big App started`.
2. The onionHEN daemon's lifecycle subscriber asks the util daemon for the runtime cheat list for `CUSA03173`, which creates the cheat session (retries for up to 3 s if the running-app query is not ready yet).
3. The util daemon **suspends the game process** (`SIGSTOP`), applies every mod whose JSON entry has `"enabled": true` (writes `on` bytes, verifies by read-back, rolls back on failure), then resumes it (`SIGCONT`). The game has just exec'd and has not run its initialisation. Timing patches (60 FPS) require this: toggling them mid-run leaves the already-initialised frame loop at its old rate and crashes on gameplay entry.
4. Because the hooks are live from the very first frame, every cave also runs while saves and maps load. Caves must therefore treat all game state as untrusted (see [30](30-code-cave-playbook.md)).
5. Mods with `"enabled": false` can be toggled later from the onionHEN cheat menu. **Caution:** runtime toggling (especially switching a camera/cave mod off) was not verified on hardware; see [70](70-onionhen-cheat-engine.md) section 4.

### The cheat JSON

```json
{ "name": "Bloodborne: Game of the Year Edition", "id": "CUSA03173", "version": "01.09", "process": "eboot.bin",
  "mods": [ { "name": "...", "type": "checkbox", "enabled": true,
              "memory": [ { "offset": "054A0780", "on": "<hex>", "off": "<hex>", "absolute": true } ] } ] }
```

* `offset` is a hex string **without** `0x`; with `"absolute": true` it is the virtual address itself. Without it onionHEN computes `0x400000 + offset` and every write lands 4 MB off (an early bug that wrote valid-looking code in the wrong place).
* `on` = bytes written when the mod is enabled, `off` = bytes written when disabled: for a hook or inline patch the original instruction bytes, for a flag byte the off value, for caves and data blocks (no original bytes) **`off` = `on`** (`build_cheats.py` fills every empty `off` with `on`, because onionHEN refuses to switch a mod off when an entry's `off` is empty; the caves simply stay in place once the hooks are restored).
* Entries of one mod are written in array order. Convention: data, caves, hooks last (flag bytes last of all).
* Two *different* mods must not write overlapping ranges (onionHEN refuses a conflicting enable; `build_cheats.py` checks it at build time).
* onionHEN keeps every patch entry in fixed 1024-byte buffers (`ONION_MAX_PATCH_BYTES`); an over-long entry is silently skipped while the hook entries are still written, so a hooked cave would be empty and crash the game at its first run. This happened with the head camera's 1761-byte manager cave (cold start crashed while live ps5debug writes, which have no such limit, worked). `tools/mods/build_cheats.py` now splits caves/data into 1000-byte chunks and asserts the limit - see [70](70-onionhen-cheat-engine.md) hazard 1.

## 3. The game, as far as it is known

* Engine family: FromSoftware's **FD4** (singletons such as LodBankMan, `FD4DebugMenuManager`), project prefix **SPRJ** (`SprjGraphics`), **Havok** physics/animation (`hkQsTransform`, `hkaPose`), **YEBIS** post-effects (Silicon Studio middleware), **Scaleform** HUD. Names come from the game's own debug strings and community convention; they are labels, not guarantees.
* The game renders at **native 1080p** in PS5 backward-compatibility mode; the video-out buffers are hard-coded 1920x1080. A 4K screenshot is the console upscaling a 1080p frame (verified: identical spectra above the 1080p Nyquist limit).
* Y is **up**. Matrices are **row-vector** convention: a model->world 3x4 stored as rows R0,R1,R2 (+ translation row R3); world point = R3 + x*R0 + y*R1 + z*R2.
* The eboot image starts at `0x400000`; code is execute-only memory (XOM) but readable through ps5debug's DMAP path; heap pointers have their high dword in `2..3` (and a low dword >= `0x10000`; packed integers like `0x1_0000_0003` and `0x5_0000_0000` are not pointers) (`0x2_0000_0000..0x7_FFFF_FFFF`).
* The game rewrites many "parameter" structures every frame from scene data (DOF, camera fields, AA parameters): **live data writes to them do not persist**; patch the consumer code or the persistent PARAM table rows instead ([10](10-memory-map.md)).

## 4. Glossary

| Term | Meaning here |
|---|---|
| **absolute** | JSON flag meaning `offset` is already a virtual address. Always `true` in this repo. |
| **AIM** | The head-camera extension that re-aims the first-person view at the lock-on target; data flag `D+0x72`. |
| **auto-apply** | Patched onionHEN applying `"enabled": true` mods at game exec time with the process suspended. |
| **bone array / pose array** | Array of 170 animated world-space 3x4 bone matrices (stride 0x30); head = bone 68. |
| **bridge host** | The Linux/macOS machine that runs the Python tooling and can reach the console. |
| **camera manager (`mgr`)** | Object `[[0x593E860]+0x2830]`; owns the pose that is sent to the renderer; copies the follow camera's pose at `0x1836C54`. |
| **cave (code cave)** | A block of our own x86-64 code (or data) written into spare memory (`0x54A0000..0x54A4000`) and entered through a hook. |
| **ChrIns** | The game's character instance object; the player is `[[0x593E878]+0x60]` (`pl`). |
| **DLAA** | Directionally localised anti-aliasing. The game has its own DLAA render pass (vtable `0x56E7980`), active by default in all tested scenes. |
| **DMAP** | Direct-map physical access used by ps5debug and onionHEN's backend to read/write process memory, bypassing page protections (and XOM). |
| **data block** | The small block of constants/flags a mod reads RIP-relatively; head camera: `D = 0x54A0E00`. Live-tunable. |
| **ack / screenshot ack** | Reply file `screenshot_ack` (`<epoch_ms> <status>`) of the screenshot hook. |
| **exec time** | The instant right after the game process is created, before it runs initialisation. |
| **FACE / FACE2** | FACE: force the player's facing every frame (rejected: tank controls). FACE2: rotate the displayed model->world rows so the body faces the camera (display only; hides coat/hood cloth). |
| **follow camera (`cam`)** | `[[[0x593E860]+0x2830]+0x60]`, the third-person chase camera; recomputes orientation as a look-at toward the pivot; never write its rows from outside. |
| **FXAA / FXAA2 / FXAA3** | Fast approximate AA shaders. YEBIS' own FXAA2 is off by default; the game pass can also run FXAA/FXAA3/FXAA3HQ via its mode field. |
| **FD4 / SPRJ** | Engine and project prefixes seen in class names and debug strings. |
| **holder** | An object hanging off the model container (`[mod+0x18]`, `[mod+0x20]`, `[mod+0x5F8]`) that contains the bone-array slots. Which holder is used changes after a respawn. |
| **hook** | A patch at an existing instruction that redirects execution to a cave. Here: `jmp rel32` (5 bytes) plus NOP padding so whole instructions are replaced. |
| **JXR** | JPEG XR, the console's screenshot format (`imagecodecs.jpegxr_decode`). `.meta` files carry `absoluteTime`. |
| **klog** | The console kernel log, streamed on port 3232. |
| **lock-on target** | Entry in the camera manager at `+0x110 + n*0x80`: target ChrIns pointer, lock point `+0x120`. |
| **MODE** | Data flag `D+0x71`: head-camera position override on. Written last when applying. |
| **mod / cheat entry** | One checkbox in the onionHEN menu = one JSON object with a `memory` array. |
| **NOCOLL** | Data flag `D+0x70`: camera collision casts return "no hit". |
| **PARAM / param blob** | FD4 parameter tables (`LOCK_CAM_PARAM_ST`, `LOD_BANK`) living on the heap; their rows are persistent data (edits stay). |
| **pose lock / call service** | Lab-only cave (tools/dev) that forces the final camera pose and runs a game function on the game thread on request. Shares addresses with the release head camera: never run both. |
| **pose object** | `[[pl+0x48]+0x18]` (vtable `0x57A0820`); before a respawn it holds the bone-array slot pointers. |
| **probe** | A line in `debug_probes.txt` telling the daemon which game values to show in the overlay DBG group; also a read-only script that inspects game memory. |
| **R/U/F** | Right/up/forward rows of a camera (R x U = F); also the head camera's offsets along them. |
| **scene (test scene)** | A recorded player position + yaw + absolute camera pose that the lab tooling can restore exactly (0.000 m error) for repeatable screenshots. |
| **slot** | Offset of one bone-array pointer inside a holder (`ARROFF`); differs between sessions, so the cave searches it. |
| **SFX-OFF** | Debug flag of the FFX effect system (`[obj+0x5C6]`); removes ground fog and sparkles and stabilises A/B images. |
| **TAA** | Temporal AA. YEBIS can do it (needs init flags), the game never enables it; enabling it showed no effect. |
| **vtable check** | Comparing `[obj]` to a known vtable address before trusting an object; the main defence against stale pointers. |
| **warm-up** | A pass over all test scenes without screenshots: a plain warp does not unload textures, so the second visit is stable. |
| **XOM** | Execute-only memory: code pages that cannot be read normally. ps5debug/onionHEN's DMAP backend can still read them. |
| **YEBIS** | Post-effect middleware (DOF, bloom, AA, tonemap) whose context lives at `[0x5865ED0]`. |

## 5. Notation used throughout

* `0x593E878` = absolute virtual address of a global; `[addr]` = 8-byte dereference; `[a+0x60]` = dereference of `a+0x60`; `[[a]+0x60]` = chained.
* Short names: `pl` player ChrIns, `X` physics body `[[pl+0x3B0]+0x68]`, `mgr` camera manager, `cam` follow camera, `D` = `0x54A0E00` (head-camera data block).
* Offsets inside a structure are always hexadecimal; struct tables are in [10](10-memory-map.md) and in [registry.json](registry.json).
* Confidence labels: `confirmed-live`, `inferred`, `static-only` (definitions in [10](10-memory-map.md)).
